覆盖的行为：

- Manifest 校验：坏 module_id、版本号残缺、minimum 高于 target、格式带点、重复格式、自依赖、缺必填字段、未知能力只警告
- 注册表：正常状态推导；未编入构建 → DISCOVERED；依赖被禁用 → BUILT 且给出原因；
  Manifest 写 status=ready 但无二进制仍是 DISCOVERED；SDK 主版本不符 → BUILT；
  二进制没有 Manifest → FAILED；缺固件 → BUILT(firmware_missing)；失败的模块可以被禁用
- 状态机：合法边、非法边、最短路径
- 存储：越权路径被拒、模块目录互不相通、重复建目录幂等、跨模块访问被记进诊断日志
- 生命周期：启动 / 单步 / 暂停 / 恢复 / 停止；停止后回到 READY；只写自己目录；
  模块自选分辨率（与宿主默认不同）也能出帧
- 故障：用户错误不污染模块、跨 ABI 异常被捕获、单模块失败不影响其它模块、
  失败粘滞直到显式重试、stop 报错仍释放实例、tick 失败后模块回到 READY 且可再次启动

## 3. iOS 构建产物（CI 实测）

GitHub Actions 的 macOS runner 用 XcodeGen + xcodebuild 打出未签名 ipa：

`
artifact: Aurora-unsigned-ipa
Payload/Aurora.app/Aurora                              235,528 bytes
Payload/Aurora.app/Info.plist                            1,077 bytes
Payload/Aurora.app/com.aurora.runtime.simulated.json       691 bytes
Payload/Aurora.app/com.aurora.runtime.ppsspp.json          774 bytes
Payload/Aurora.app/com.aurora.runtime.empty.json           524 bytes
Payload/Aurora.app/com.aurora.runtime.faultinjector.json   655 bytes
`

- Mach-O 魔数 `CF FA ED FE`（64 位），cputype `0x0100000C` → arm64
- `CFBundleIdentifier` = com.aurora.app，`MinimumOSVersion` = 16.0
- 构建所用 SDK：iPhoneOS 26.5

这一步证明"能编译出真机架构的 App 且资源打进去了"。**没有证明**"在真机上能启动"——
那需要签名安装到设备，见第 4 节。

## 4. 还没有证据的部分

- iOS 真机运行：ipa 已产出，尚未签名安装到设备

- 多模块并发：只验证了"一个失败另一个可用"，没验证两个同时跑满帧率
- 崩溃恢复：段错误场景无法在单元测试里制造，只有设计说明
