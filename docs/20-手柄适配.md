# 手柄适配

## 现状（已实现）

App 启动时初始化 `Gamepad`（`Apps/Aurora-iOS/Sources/Gamepad.swift`），监听
`GCControllerDidConnect` / `DidDisconnect`，并对每个已连接手柄以 60Hz 轮询。

| 输入 | 行为 |
|---|---|
| D-pad / 左摇杆 | 移动虚拟指针（每 0.22 秒一步，每步 2% 屏宽） |
| A 键 | 在指针当前位置点击 |
| 左摇杆数值 | 经 `aurora_bridge_set_pad` 送进模块（留给以后需要方向输入的游戏） |

播放页在检测到手柄时画一个半透明圆点表示指针位置；没有手柄时不显示。

蓝牙与 USB 手柄在 iOS 上是同一套 `GCController`，无需区分。

## 为什么不用引擎键盘事件

ONScripter / KiriKiri 的游戏内菜单大多是自己绘制的图片按钮，靠鼠标位置判定。
把 D-pad 映射成方向键需要改引擎库并重编（引擎是预编译的 `.a`），而"虚拟指针 + 点击"
走的正是游戏已经在用的鼠标通道，**不用改引擎**就能选菜单。
