# 15 安全审查

日期：2026-11-09。范围：公开仓库 ProjectAurora 的全部跟踪文件、GitHub Actions 配置、
iOS 应用的配置与权限。结论按"已核对 / 已修 / 残余风险"三类写。

## 1. 仓库内容

用 $git grep$ 扫了 228 个跟踪文件，找私钥、证书、口令、token、API key、UDID、邮箱：

- 没有私钥、证书、$.p12$、描述文件
- 没有 token / API key / 口令
- 没有设备 UDID（之前那份 $sideloadlydaemon.log$ 已在早期提交里删掉并改写过历史）
- 没有个人路径（$C:\Users\$、$D:\$）、没有内网地址、没有邮箱
- 文档里提到 "Apple ID" 只是安装步骤说明，不含真实账号

$.gitignore$ 覆盖 $build/$、$out/$、$*.ipa$、$*.log$、$third_party/$，
本地日志与依赖树不会进仓库。

## 2. 应用配置

- $Info.plist$ 只多了 $UIFileSharingEnabled$ 和 $LSSupportsOpeningDocumentsInPlace$（导入游戏需要）
- 没有 $NSAppTransportSecurity$ 例外，没有任意网络加载
- 没有 entitlements 文件（未签名构建）
- 模块存储层对 module id 和相对路径都做了校验，并且在规范化之后再做一次前缀比对，
  防止 $../$ 逃逸（$Tests/src/test_storage.cpp$ 有对应用例）

## 3. 已修：CI 里的 token 暴露面

原来的写法有两个问题：

1. $actions/checkout$ 默认把 token 写进 $.git/config$。而我们的 spike 作业会
   $git clone$ 并**编译第三方源码**（SDL、ONScripter、移植工程），
   这些构建脚本运行在同一作业里，读得到 $.git/config$ 就等于拿到了写权限 token。
2. 状态文件靠 $git push$ 提交，token 隐含在 checkout 凭据里。

改法：

- 全部 $checkout$ 加 $persist-credentials: false$
- 只有发布状态那一步显式拿 $github.token$（步级 $env$，不是作业级）
- push 时用带 token 的显式 URL，不依赖本地 remote 配置

## 4. 残余风险（没有完全解决，如实列出）

- **上游供应链**：spike 作业拉的是上游分支头（$--depth 1$，不带 commit pin），
  上游被篡改会进入我们构建的产物。彻底做法是钉死 commit SHA 并定期手动升级。
- **Actions 版本**：用的是 $@v4$ 这类大版本标签，不是 commit SHA。官方 action 被投毒的概率低，
  但不是零。
- **公开仓库里的包名**：$com.aurora.app.FLLX2685CW$ 里的后缀是免费账号的 team id。
  它不是凭据，但会暴露"这个包由哪个免费账号签的"。
- **文件共享**：开了 $UIFileSharingEnabled$，能接触到设备的人可以读写 App 的 Documents。
  侧载场景下这是刻意的取舍。
- **构建产物本身**：CI 产物没有做签名校验与来源证明（artifact attestation），
  打包下载后无法证明它确实来自这次提交。
