# 03 模块生命周期与故障管理

对应任务书 Phase 3 交付物 07、09。实现位置：`SDK/AuroraModuleSDK/src/supervisor.cpp`、
`state_machine.cpp`、`registry.cpp`。

## 1. 生命周期详解

（Diagram in state_machine.cpp; text version below.)

1. **注册**：平台读 Manifest → 校验 → 入表（此时还不知道二进制在不在）
2. **绑定**：构建表给出 link 进来的模块 → 校验 vtable → 绑定
3. **求值**：算派生状态（READY / BUILT / DISCOVERED / DISABLED / FAILED）
4. **启动**：create_instance → load_game → start
5. **运行**：tick 或模块自循环
6. **停止**：stop → release_instance → 释放绑定
7. **失败**：拆实例 → 释放绑定 → 判定致命/可重试 → 置 FAILED 或回 READY

每个阶段的所有权：

| 阶段 | 谁拥有内存 | 失败时谁清理 |
|---|---|---|
| create_instance | 模块 | 模块自己（平台只调 release_instance） |
| load_game | 模块 | 平台调 release_instance |
| start | 模块 | 平台调 stop（若已 start）再 release |
| 运行期帧缓冲 | 平台 | 平台 |
| 存储路径 | 平台 | 平台 |

## 2. 状态机规则

- 只允许表里的边，非法迁移被拒绝并记 `transition_error`
- 派生状态需要跨多个状态时，走最短合法路径
- 失败状态粘滞，只有 `resetFailure()` 能清

粘滞是有代价的：用户必须手动点重试。这是刻意的取舍——自动恢复会把"每次启动都崩"
伪装成"偶尔小毛病"。

## 3. 故障分类与处理

**可重试（用户错误）**：UNSUPPORTED_GAME、MISSING_FIRMWARE、IO、CANCELLED、TIMEOUT
→ 拆实例，模块回 READY，用户换个游戏再来

**致命（模块缺陷）**：INIT_FAILED、INTERNAL、ABI_MISMATCH、OUT_OF_MEMORY、STATE
→ 拆实例，模块置 FAILED，存档与配置保留

**违规（越权）**：模块请求别的模块的目录、伪造日志来源
→ 回调拒绝，记违规文本，不影响其它模块

## 4. 进程内崩溃：能做什么，不能做什么

能：

- 捕获返回值错误
- 捕获跨 ABI 的 C++ 异常（`fault_exception_across_the_abi_is_caught` 验证）
- 释放实例、释放绑定、标记失败、保留数据
- 让其它模块继续工作（`fault_a_failed_module_leaves_the_others_working` 验证）

不能：

- 拦截 SIGSEGV / SIGBUS / 栈溢出 / 堆破坏——整个进程会退出
- 强制杀死卡死的模块（没有抢占式看门狗）

真正的隔离只有两条路，都属于后续架构变更：

1. 独立进程 + 共享内存传帧（iOS 上受后台与内存限制，延迟也会上升）
2. 系统扩展/服务（iOS 不允许自定义常驻服务）

**因此规范里不允许出现"模块崩溃不影响主程序"这种无条件的说法。** 正确表述是：
"模块返回的错误与抛出的异常不会影响其它模块；进程级崩溃会带走整个 App。"

## 5. 版本与兼容

- SDK 版本：主版本不同 = 不兼容；宿主次版本必须 ≥ 模块编译时版本
- 模块版本：Manifest 声明，二进制自报，两者不一致只警告（Manifest 为准）
- 存档：模块自己负责格式，平台负责提供目录与备份；平台从不解析存档内容
- 回退：模块升级失败时保留旧目录，由用户在 UI 里选择回退（尚未实现 UI）

## 6. 缺失与禁用

| 场景 | 表现 |
|---|---|
| Manifest 有、二进制没编进来 | DISCOVERED，原因 "not compiled into this build" |
| 二进制编进来、Manifest 没有 | FAILED，"module was linked in without a manifest" |
| 用户禁用 | DISABLED，数据保留，再次启用回到原状态 |
| 依赖被禁用 | BUILT，原因 "dependency_not_ready:<id>" |
| SDK 不兼容 | BUILT，原因 "sdk:sdk_major_mismatch" |
| 缺固件 | BUILT，原因 "firmware_missing" |

这些都是**已有单元测试覆盖**的行为，不是设想。
