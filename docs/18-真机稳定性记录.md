# 真机稳定性记录（iPad, iOS 26.6）

设备：iPad16,3 / 26.6 / UDID 00008132-000508610A85801C
测试方式：Sideloadly 签名安装 + pymobiledevice3 驱动（启动、截图、日志、崩溃报告）

## 1. 启动即崩：dyld 找不到 libSDL2

现象：装好后点图标立刻退出。
崩溃报告（`Aurora-2026-11-13-234759.000.ips`）：

```
DYLD, Library missing
Library not loaded: @rpath/libSDL2-2.0.0.dylib
Reason: tried '/usr/lib/swift/...', '.../Aurora.app/Frameworks/...'
```

dyld 试过的路径里没有 `Aurora.app/` 根目录——app 二进制缺 `@executable_path` 这条 runpath。
修复：`project.yml` 加

```yaml
LD_RUNPATH_SEARCH_PATHS:
  - "$(inherited)"
  - "@executable_path"
```

验证：直接解析 ipa 内 Mach-O 的加载命令，`LC_RPATH` 含 `@executable_path`，且包内有 `Payload/Aurora.app/libSDL2-2.0.0.dylib`。
CI 增加"装载检查"步骤：列出 `LC_RPATH`、逐个确认 `@rpath` 依赖能在包内找到，缺一个就让构建失败。

## 2. 真机自测（app 内循环）

启动参数：

```
-AuroraSelfTest 1 -AuroraSelfTestRounds 3 -AuroraSelfTestHold 8
```

app 自己按 KiriKiri → ONScripter 顺序 start/stop，每条结果写 `Documents/boot.log`。
自测必须让"运行面板"出现，否则宿主不给画布，`present_frame` 全部被拒、帧数恒为 0（第一版就是这个错）。

## 3. ONScripter：可用

三轮实测帧数 240 / 242 / 243（8 秒窗口，约 30fps），无崩溃。

修复的崩溃：引擎致命错误路径里的 `exit(-1)` → `atexit(SDL_Quit_Wrapper)` → 在引擎线程销毁 SDL 窗口 → UIKit 断言 -> abort。
构建时把 `ScriptHandler.cpp` 里三处 `exit(-1)` 改成 `throw 7101`，绑定层 `catch (int)` 后返回错误码，进程不再被杀。

文字异常（未闭环）：截图首字符是方框。`0.utf` 行首是全角空格（UTF-8 `e3 80 80`），引擎的对话标记是 Shift-JIS `0x81 0x40`，识别不了就当普通字符渲染，Lato 没有该码位 → 方框。
另外 `copyBundledTestGames()` 原来"目标存在就跳过"，导致修好的剧本永远到不了设备；已改成每次启动先删再拷。

## 4. KiriKiri：只能开一次游戏（已知限制）

首轮 `start=0, frames=237`；第二轮起要么 `start=5 (io_error)`，要么（跳过 open 后）`start=0, frames=0`。
原因：运行时的 `engine_open_game` 一个进程只接受一次，`engine_destroy`+重建、`engine_resume` 都救不回来。
现状：同一标题重启不会再报错，但没有画面；真要重开得重启 App。

## 5. 操作层面的坑

- Sideloadly 安装卡在 88%：旧版 app 还在运行，先 `developer dvt pkill --bundle` 杀进程再装。
- 从电脑启动 app：`developer dvt launch '<bundle> -Key value'`，启动参数会进 UserDefaults。
- 取应用沙盒文件：`apps pull <bundle> Documents/boot.log <本地路径>`。
- 取崩溃报告：`crash ls` / `crash pull <输出目录> <文件名>`。


## 6. 文字方框：已修

真机截图行首的方框，根因是 `drawChar()` 的这句：

```cpp
if ( !isNonPrinting(&out_text[0]) || script_h.enc.getEncoding() == Encoding::CODE_UTF8 ){
```

UTF-8 模式下条件恒为真（引擎有意画出所有字符，因为 UTF-8 空格宽度不固定），于是对话标记 U+3000 也被画出来；Lato 没有该码位 → 方框。
只改 `isNonPrinting()` 没用，会被这个 `||` 短路。最终补丁在绘图条件里单独排除 U+3000。

验证截图：`docs/evidence/device-ons-text-clean.png`（行首方框消失）。

另外 `copyBundledTestGames()` 原来"目标存在就跳过"，导致改过的剧本永远到不了设备；已改成每次启动先删再拷。

## 7. KiriKiri 重启：明确拒绝

`engine_api.h` 里没有 `close_game`，运行时代码里写得很直白（`bridge/engine_api/src/engine_api.cpp`）：

```cpp
if (g_runtime_started_once) {
  return SetHandleErrorAndReturnLocked(
      impl, ENGINE_RESULT_NOT_SUPPORTED,
      "runtime restart is not supported yet; restart process to open another game");
}
```

即"重启进程才能打开另一个游戏"是上游明说的限制，不是我们的用法问题。实测：

| 做法 | 结果 |
|---|---|
| stop 时 destroy，再 start | `start=5 (io_error)` |
| stop 时保留引擎，再 start | `start=0` 但 `frames=0` |
| 保留引擎 + `engine_resume()` | `start=0` 但 `frames=0` |
| 直接拒绝重启 | `start=2 (unsupported)`，界面给出原因 |

现状选最后一种：不再伪装运行，重启后提示需要重启 App。

## 9. 触控：已接通

`MetalFrameView` 只有一个裸 `MTKView`，没有任何触摸回调，`aurora_bridge_set_touch()` 从来没人调——面板只出画面，手指完全被忽略。
已加 `TouchMTKView`，四个回调把触摸位置归一化后转发。

真机验证：启动后点一下画面，文字从第一句变成第二句（截图 `device-touch-before.png` / `device-touch-after.png`）。

测试剧本只有两句，用 `click` 分隔；第二句之后再点没有下一句，所以"点第二下没反应"是剧本到头的正常表现。
