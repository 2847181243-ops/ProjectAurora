# 前端设计（v1）

目标：打开就是游戏库，玩家永远不需要知道"引擎/模块"这回事。

## 1. 信息架构

```
游戏库（唯一入口）
├── 点卡片 → 游戏页
│             ├── 开始游戏 → 全屏播放页
│             └── 其他游戏（横向）→ 换一个游戏页
└── 齿轮 → 设置
             ├── 外观：背景、玻璃透明度、字体颜色、经典玻璃对比
             ├── 游戏库：路径、重新扫描、导入
             └── 版本（连点五次）→ 开发者：引擎列表、诊断日志
```

## 2. 游戏库

两列网格（手机）/ 自适应多列（平板），2:3 竖版卡片。

封面优先读游戏目录自带的图，按 `cover → thumbnail → thumb → title → logo → icon → package → banner` 的顺序找，
扩展名 `png/jpg/jpeg/webp/bmp`。找不到就用标题哈希出的稳定色块加首字母。

库只列**被引擎认领**的游戏；认不出的文件不显示，点了会说明缺什么入口文件。

## 3. 游戏页

左封面、右标题 + 片头 + 开始游戏，下面一排其他游戏。

片头分三条路：

| 格式 | 处理 |
|---|---|
| mp4 / m4v / mov | 系统 `AVPlayer` |
| mpg / mpeg | 软解（pl_mpeg，逐帧画到 CALayer） |
| wmv / avi | 显示"暂时没有解码器" |

## 4. 播放页

全屏、黑底、画面按比例居中、整屏是触摸区。轻点呼出控制条（返回 / 停止 / 帧率），三秒自动淡出。

## 5. 玻璃

两套实现共存，编译期和运行期各一层判断：

```swift
if #available(iOS 26.0, *) {           // 系统够新
    #if compiler(>=6.2)                 // 工具链认识这个 API
    content.glassEffect(.regular, in: shape)
    #endif
} else {
    content.modifier(GlassSurface(...)) // 材质模拟
}
```

经典那套是 `.ultraThinMaterial` + 6% 白底 + 左上到右下的渐变描边 + 阴影。
玻璃要"像玻璃"必须有东西可采样，所以库里垫了一层背景光：第一张封面模糊 60pt、35% 透明，再叠暖橙和冷蓝两个大色块。

透明度可调（0–45%，默认 4%），存在 `appearance.glassAlpha`；"跟随背景自动"按底图亮度和深浅色算，默认关。

## 6. 无真机验证手段

CI 里点不了屏幕，所以 App 认三个启动变量：

| 变量 | 作用 |
|---|---|
| `AURORA_AUTOSTART` / `AURORA_AUTOSTART_GAME` | 启动即跑某个模块（CI 用） |
| `AURORA_OPEN_DETAIL` | 启动后自动推进某个游戏的页面 |
| `AURORA_SELFTEST` | 循环启停两个引擎并记录帧数 |

`krkr-sim-app.yml` 会带着这些变量启动模拟器并截两张图。
