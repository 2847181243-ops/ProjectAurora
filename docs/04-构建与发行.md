# 04 构建与发行

对应任务书第十一节、Phase 4 的工程部分。

## 1. 两套构建，一份代码

| 用途 | 工具 | 在哪跑 | 产物 |
|---|---|---|---|
| 平台层单元测试 | CMake + Ninja | 任意桌面（Windows/macOS/Linux） | `aurora_core_tests` |
| 无头宿主 / 帧导出 | CMake + Ninja | 桌面 | `aurora-cli` |
| iOS App | XcodeGen + xcodebuild | macOS（本地或 CI） | `Aurora.app` / unsigned ipa |

三个平台的主机测试在 CI 里都通过（ubuntu / macos / windows），这是"平台层不依赖 Apple 框架"的实证。

## 2. 为什么 iOS 侧用 XcodeGen 而不是提交 .xcodeproj

`project.pbxproj` 是多人同时改必然冲突的二进制式文本。用 `project.yml` 描述工程，
每次构建现生成，冲突面归零。CMake 只负责桌面与测试，不去生成 Xcode 工程——两套工具各管一段，
边界清楚。

## 3. 模块表：两处生成，一份来源

- CMake 侧：`BuildSystem/AuroraModules.cmake` 读 `Modules/modules.list` 生成 `AuroraBuiltinModules.cpp`
- Xcode 侧：`BuildSystem/generate_builtin_table.py` 读同一个文件生成同一份内容

单一事实来源是 `Modules/modules.list`。新增模块只改这一行 + 目录 + Manifest。

## 4. Windows 上的本地工具链（特殊说明）

开发机没有 Visual Studio。当前用 zig 0.17.1 的 clang 22 作为 C/C++ 编译器
（`zig cc / zig c++`），CMake 用 ARG1 方式驱动，静态库归档走 `zig ar`。
CMakeLists 里有一段显式处理（匹配到 zig 时改写归档规则）。

这段只影响 Windows 本地开发，macOS CI 与 Xcode 全走原生 clang，不经过它。

## 5. 未签名 ipa 流水线

`.github/workflows/ios.yml`：

1. 生成模块表
2. `brew install xcodegen`
3. `xcodegen generate`
4. `xcodebuild archive`，关闭签名（`CODE_SIGNING_ALLOWED=NO`）
5. 打成 `Payload/Aurora.app` + zip → `Aurora-unsigned.ipa`
6. 作为 artifact 上传

实测产物（2026-11-08 构建）：

- 文件：`Aurora-unsigned.ipa`，78,241 字节
- 可执行文件：`Payload/Aurora.app/Aurora`，235,528 字节
- Mach-O 魔数 `CF FA ED FE`（64 位），cputype `0x0100000C`（arm64）
- `MinimumOSVersion` 16.0，`CFBundleIdentifier` com.aurora.app
- 构建 SDK：iPhoneOS 26.5（Xcode 16 / DTXcode 2660）

## 6. 从 ipa 到真机

未签名 ipa 不能直接装。需要在 Windows 侧用签名工具（Sideloadly 一类）配合 Apple ID 签名后安装。
免费 Apple ID 的签名 7 天失效，需要重签；付费开发者账号一年。

平台本身的架构不受这一步影响——它只是分发手段。
